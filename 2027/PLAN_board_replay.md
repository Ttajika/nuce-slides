# 計画：先生の板書レイヤーと再生モード

対象：`micro_MG.html`（初級ミクロ経済学スライド）
関連：`slide-live.js`（配信・録画）, `slide-sync.js`（クラウド同期）

## 目的

オンデマンド授業で、動画とは別に「スライドそのものが板書つきで動く」体験を作る。
段階的に作り、各段階が単独でも使えるようにする。

1. **段階1**：先生の板書を学生のスライドに重ねて表示できる
2. **段階2**：板書を書き順どおりに再生できる（音声なし）
3. **段階3**：トピックごとに音声つきで再生でき、スライドも自動でめくれる

## 作業前に確認すること（Claude Code への指示）

- `slide-live.js` と `slide-sync.js` を先に読み、既存の録画（`&rec=1`）・配信の仕組みで再利用できる部分を洗い出す。重複実装は避ける。
- `micro_MG.html` の既存の描画処理（`strokes`, `redrawStrokes`, `canvasPoint`, `initPencilDetection`, `exportData` の正規化）を把握してから着手する。
- 学生の書き込みデータ（`localStorage` の `STORAGE_KEY`）の形式は変えない。既存の学生データを壊さないこと。

## 段階0：下準備（小さな修正）

- [ ] **スライドに安定IDを付ける**：各 `<template class="slide-data">` に `data-id`（例：`supply-demand-eq`）を追加し、`SLIDES[i].id` として読む。スライドは作りかけで今後挿入・削除があるため、板書データはインデックスではなくIDで紐づける。
- [ ] `data-id` が未設定のスライドには読み込み時に警告を出す（開発用）。
- [ ] セクション名の表記ゆれを修正：「売り方の設計」配下のスライドが `data-section="独占市場"`、最後が「分野案内」と「Final Remark」に分かれている。
- [ ] `parseVimeoUrl` で `#t=` を引き継ぎ、トピックごとの頭出しリンクを作れるようにする。

**完了条件**：目次が意図どおりのセクションで並ぶ。全スライドに `data-id` がある。

## 段階1：先生の板書レイヤー

### 表示（学生側）
- [ ] 学生用 `#drawCanvas` の下に、先生用 `#teacherCanvas` を追加（`pointer-events:none`）。
- [ ] 板書データを `board/micro_MG.board.json` から `fetch` で読み込む。存在しなければ何もしない。
- [ ] トップバーに「👁 板書」ボタン（ショートカット `T`）。表示状態は `localStorage` に保存。
- [ ] スライド切り替え・ズーム・リサイズ時に再描画（既存の `showSlide` / `applyZoom` / `resize` にフック）。
- [ ] 印刷モードでは既定で非表示（任意でONにできると良い）。

### 記録（先生側）
- [ ] `?author=1` で作成モード。このモードではペン入力を先生レイヤーに記録し、学生用 `localStorage` には保存しない。
- [ ] 各ストロークに開始時刻と点ごとの経過時間を記録する（段階2・3のため、**段階1の時点から必ず記録する**）。
- [ ] 消しゴム・取り消し・全消去も操作ログとして記録する。
- [ ] 「板書を書き出し」ボタンで JSON をダウンロード。

### 座標の扱い（要判断）
レイアウトは画面幅で変わるため、線と本文がずれる問題がある（`live-fixed` クラスで対処している問題と同じ）。
- 案A：記録時・表示時ともに基準幅（`.zoom-layer` の `max-width:1100px`）で固定レイアウトにし、座標は基準幅で正規化。表示時はズームで拡縮。
- 案B：`exportData` と同様に canvas の幅・高さで正規化（実装は簡単だが、幅が違うとずれる）。
- **推奨は案A**。板書表示中は `body.live-fixed` 相当を適用する。

**完了条件**：iPad＋Apple Pencil で作成モードで書き、書き出したJSONを置くと、PC・iPad・スマホ幅で学生側に板書が重なって表示される。学生の書き込みとは独立して消えない。

## 段階2：書き順どおりの再生（音声なし）

- [ ] 板書ONのスライドに「▶ 板書を再生」ボタン。押すと先生レイヤーを空にして、記録された時刻どおりに線を描いていく。
- [ ] 再生速度（1x / 2x / 4x）と、空白時間の自動短縮（例：線と線の間が3秒以上なら1秒に詰める）。
- [ ] 一時停止・最後まで飛ばす。
- [ ] 再生中も学生は自分のペンで書き込める。

**完了条件**：式変形のスライドで、書き順どおりに板書が現れる。

## 段階3：トピックごとの音声つき再生

### データ形式（案）
```json
{
  "version": 1,
  "deck": "micro_MG",
  "ref": { "w": 1100 },
  "strokes": {
    "<slide-id>": [
      { "id": "k1", "color": "#e94560", "size": 3, "alpha": 1,
        "points": [[x, y, dt], ...] }
    ]
  },
  "topics": [
    {
      "section": "需要と供給",
      "audio": "audio/supply-demand.m4a",
      "events": [
        { "t": 0.0,  "type": "slide",  "id": "<slide-id>" },
        { "t": 12.3, "type": "stroke", "slide": "<slide-id>", "stroke": "k1" },
        { "t": 40.1, "type": "erase",  "slide": "<slide-id>", "strokes": ["k1"] },
        { "t": 55.0, "type": "pointer", "x": 0.4, "y": 0.3 }
      ]
    }
  ]
}
```
- `t` はトピック音声の先頭からの秒数。
- 座標は段階1で決めた正規化方式に従う。

### 再生（学生側）
- [ ] セクション扉スライドに「▶ このトピックを再生」ボタン（`SECTIONS` と `topics[].section` を対応づける）。
- [ ] `<audio>` の `currentTime` を時計にして、`requestAnimationFrame` でイベントを適用（スライド移動・線の描画・消去・ポインタ）。
- [ ] シークバー（既存のアニメ図の `.anim-ctrl` のデザインを流用）。シーク時は「その時刻までの状態」を作り直して描画。
- [ ] 再生中に学生が自分でスライドを移動したら一時停止し、「再生位置に戻る」ボタンを出す。
- [ ] 再生速度変更（`audio.playbackRate`）。

### 記録（先生側）
- [ ] 作成モードで「● トピック録音開始／停止」。`MediaRecorder` で音声を録りながら、同じ時計でイベントを記録。
- [ ] 録音停止で音声ファイルとJSONを書き出し。
- [ ] 録音の一時停止に対応（一時停止中はイベントの時計も止める）。手書き中の一時停止運用と合わせるため。
- [ ] Safari でも再生できる形式（m4a/AAC 推奨）。録音形式が webm の場合は変換手順を README に書く。

**完了条件**：1トピック分を録音し、学生側で再生ボタンを押すと音声に合わせてスライドがめくれ、板書が書かれていく。シークしても状態が正しい。

## 共通の確認項目

- [ ] iPad Safari＋Apple Pencil、PC Chrome、スマホ幅（≤768px）で動作確認
- [ ] ズーム（70%〜250%）で線がずれない
- [ ] 印刷モードに影響しない
- [ ] 板書JSONや音声がない場合、従来どおりに動く（後方互換）
- [ ] 学生の既存データ（メモ・手書き・理解度・ブックマーク）が保持される

## 進め方

- 段階ごとにブランチ／コミットを分ける。段階0→1→2→3の順。
- 各段階の終わりに動作確認し、次に進むか判断する。
- 段階3は「できたらいいこと」。段階1・2だけでも運用できる状態を優先する。
